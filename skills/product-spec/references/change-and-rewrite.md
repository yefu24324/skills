# 变更与重写规则

规则版本：`2.0`

## 判断原则

先识别变化影响的实体、关系和不变量，再选择 `PATCH` 或 `REWRITE`。判断依据是产品含义和结构是否改变，不是修改字数。

## 使用 PATCH

仅在实体目的、边界和关键关系保持不变时局部修改，例如：

- 文案或说明更清楚；
- 增删局部字段；
- 调整一个明确的校验规则；
- 补齐不改变主流程的次要状态；
- 修复断裂引用或验收表述。

完成后仍需沿关系检查受影响的页面、流程、规则和验收。

## 使用 REWRITE

以下任一项改变时，完整重写受影响实体的当前版本：

- 产品目标、范围或能力边界；
- 角色、权限或可见性；
- 主流程、重要分支或完成结果；
- 核心对象的含义、归属或生命周期；
- 页面主要职责、导航或区域关系；
- 共享业务规则或系统边界；
- 原文已经形成互相依赖的补丁链。

`REWRITE` 不等于重写所有产品文档。仅重写受结构变化影响的完整实体，并同步所有入向与出向引用。

## 禁止补丁堆积

不要通过“补充”“后来增加”“特殊情况”“旧逻辑仍保留”等段落维护已经错误的结构。当前规格只保留当前真实需求；历史原因和被替代方案进入 Decision 或版本历史。

## 变更步骤

1. 列出新增、修改、删除的实体和关系。
2. 标记直接影响与关系传播影响。
3. 对每个受影响实体选择 `PATCH` 或 `REWRITE` 并说明原因。
4. 对无法从证据决定的高影响问题创建阻塞 Clarification。
5. 修改完整当前规格并移除失效文本。
6. 校验稳定 ID、引用、不变量和追踪矩阵。
7. 固定新 revision，交给独立 Reviewer。
