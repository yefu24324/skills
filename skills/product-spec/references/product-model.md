# 共享产品模型

模型版本：`4.0`

本文件定义三个 product-spec 技能共同遵守的最小产品模型。具体分析方法、字段组织和文档形式由 Agent 根据任务自主决定。

## 当前规格

- 当前规格只描述当前有效的产品意图，不把历史补丁混入正文。
- 事实、推断、低影响假设和开放决定必须可区分。
- 无法由证据确定的高影响产品取舍必须由人类决定。
- 每个正式 revision 必须有明确版本，并由独立 Reviewer 审阅。
- 正式规格优先使用稳定的中文名称和 Markdown 链接追踪关系，不用内部编码替代产品含义。

## 核心内容

按任务实际需要使用以下实体，不为填满模型而虚构内容：

- **产品定义**：目标、范围、非目标、用户与成功信号。
- **用户角色**：用户目标、权限和可见范围。
- **产品能力**：为用户提供的完整能力、业务价值及其边界。
- **业务对象**：业务含义、归属、关系和生命周期。
- **业务流程**：触发、前置条件、主要步骤、重要分支、失败恢复与结果。
- **页面**：解决的问题、使用场景、用户任务、功能区域、操作结果、状态和权限。
- **功能区域**：页面内具有明确产品职责的一组内容与操作。
- **用户操作**：用户意图、可用条件、操作效果、反馈、失败行为和权限。
- **业务规则**：条件、结果、例外、适用范围和依据。
- **业务与界面状态**：状态含义、进入条件、迁移与用户可见行为。
- **验收标准**：可观察、可测试并能追踪到相关需求的验收结果。
- **产品决定**：需要保留原因、取舍、影响和替代关系的决定。
- **标杆对比**：标杆的相关性、依据与时效、可迁移原则和不适用部分。
- **候选方案**：主动扩写发现的缺口、可选方案、推荐、取舍、影响范围和人类确认状态。
- **待确认问题**：证据不足且需要人类决定的问题、影响、状态和结论。
- **审阅记录**：固定 revision 的审阅范围、独立 Reviewer、问题、修改要求和结论。

每项内容使用稳定、明确且不重复的中文名称。跨文件关系优先通过文件名、中文标题锚点和 Markdown 链接追踪。

## 需求目录

默认在 `docs/product/` 维护当前产品规格；项目已有明确的产品规格根目录时沿用，不重复创建。根目录只固定以下结构：

```text
docs/product/
├─ index.md     产品需求唯一入口
├─ features/    产品能力、目标与范围
├─ flow/        用户流程与业务流程
├─ pages/       页面及页面结构
└─ shared/      跨能力共享的产品规则
```

- `index.md` 必须存在，并提供当前产品范围、能力地图、流程入口、页面地图和共享规则入口。
- 按实际内容创建目录和文件，不生成空文档；文件粒度和子目录由 Agent 自主决定。
- `index.md` 只负责导航和概览，不复制各规格文件的完整正文。
- 新增、移动、重写或删除规格时同步更新 `index.md`，不得留下孤立文件、断裂链接或失效入口。
- 不为治理记录固定额外目录；确需保存时，沿用项目已有约定或由 Agent 选择合适位置。

## 必须维护的关系

- 产品能力必须落到流程、页面或明确的非可视行为。
- 流程必须关联执行角色、涉及对象、规则、结果和适用页面。
- 用户流程和业务流程必须按流程结构规范使用 Mermaid 表达，并与配套 Flow 规格一致。
- 页面必须说明关联能力、使用场景和用户任务，并用功能区域表达主要内容与操作。
- 用户操作必须关联所属功能区域、操作效果、反馈、权限、规则和验收。
- 对象状态必须与流程、页面行为和规则一致。
- 验收必须追踪到一个或多个产品实体。
- 决策、待确认问题和审阅记录必须关联受影响内容或 revision。
- 标杆对比必须关联候选方案或受影响内容；只有已接受或修改的候选方案能进入正式规格。

## 必须始终成立的质量条件

Reviewer 使用以下中文名称报告问题，不要求读者记忆质量编号：

1. **名称与引用有效**：中文名称稳定、含义明确，跨文件链接有效。
2. **产品关系闭环**：不存在孤立需求、断裂引用、互相矛盾的权限或无法闭环的核心流程。
3. **共享规则唯一**：共享规则只有一个权威定义，其他位置只引用并说明其对当前内容的影响。
4. **状态行为一致**：业务对象状态、流程迁移、页面行为和规则一致。
5. **用户行为可验收**：重要操作具有明确效果、反馈、失败处理、权限和可测试验收。
6. **当前需求无补丁链**：当前规格不依赖已被替代的需求，也不以补丁链表达当前行为。
7. **假设没有伪装成需求**：假设或开放问题不得静默变成已确认要求。
8. **审阅范围已经确定**：提交审阅时，不得存在影响该 revision 的开放阻塞决定。
9. **编写与审阅相互独立**：Author 与 Reviewer 使用不同 context；Reviewer 不得参与被审 revision 的调查、协调或编写。
10. **独立审阅后才能完成**：没有独立审阅记录的 `APPROVED`，revision 不得通过产品阶段。
11. **打回后产生新版本**：`CHANGES_REQUESTED` 产生新 revision；`HUMAN_DECISION_REQUIRED` 在取得人类决定前暂停受影响工作。
12. **目录覆盖完整**：`index.md` 覆盖所有当前规格入口，不存在孤立规格、断裂链接或失效入口。
13. **许愿式输入经过确认**：许愿式输入经过标杆对比和主动扩写；未经人类确认的高影响候选方案不得进入正式规格。
14. **流程完整可读**：用户流程和业务流程具有可解析的 Mermaid 图，主路径、重要分支、失败恢复和完成结果闭环。
15. **页面无需解码即可理解**：读者无需查阅内部代号或其他文件，就能理解每个页面的用途、主要任务、功能区域、操作结果和异常恢复。

追踪形式由 Agent 自主选择，但正式规格优先使用中文标题与 Markdown 链接，必须能从目标追踪到相关角色、对象、流程、页面、规则和验收，也能反向定位来源与决定。
