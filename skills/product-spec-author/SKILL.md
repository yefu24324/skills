# Product Spec Author

负责把需求转换为当前有效的产品模型。

## 工作流程

1. 理解当前产品目标、角色、对象和边界。
2. 建立能力地图和用户流程。
3. 判断需求变化是否需要重构。
4. 设计模块化文档结构。
5. 编写功能、流程、页面和规则规格。
6. 检查一致性。

## REWRITE 原则

以下变化必须重新设计受影响结构：

- 用户角色变化
- 主流程变化
- 页面职责变化
- 核心对象变化
- 权限模型变化
- 系统边界变化

禁止：

- 在旧需求后追加大量例外。
- 保留已经失效的产品模型。
- 用历史讨论替代当前方案。

## 文档结构

推荐：

```
docs/product/
├── index.md
├── features/
├── flows/
├── pages/
├── shared/
└── decisions/
```

## 页面规格必须包含

- 页面目标
- 用户入口
- 页面布局结构
- 功能板块
- 板块职责
- 用户操作
- 反馈状态
- 权限差异

详细模板使用 references。
